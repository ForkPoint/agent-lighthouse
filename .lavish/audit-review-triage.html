SHARED HELPER (`_robots-txt-helpers.ts`) — its defects propagate to 24 of the 28 audits:

1. BOM blindness (high). `parseRobotsTxt` splits lines and does `line.slice(0, colonIdx).trim().toLowerCase()`. A UTF-8 BOM makes the first directive `﻿user-agent`, which matches nothing, so the entire first group is silently discarded. RFC 9309 explicitly requires crawlers to ignore a leading BOM. A BOM'd `User-agent: *\nDisallow: /` parses to ZERO groups → `no-blanket-block` returns PASS on a site that blocks the entire web. BOM'd robots.txt is common from IIS/Windows and CMS exporters. Fix: `body.replace(/^﻿/, '')`.

2. Exact-string user-agent matching (high). `isAllowed` uses `g.userAgent.toLowerCase() === botName.toLowerCase()`. Real robots.txt frequently carries versioned/product tokens — `User-agent: CCBot/2.0` is the form Common Crawl's own historical docs and thousands of sites use; `GPTBot/1.1` also appears. Those groups are invisible to the audit, so a site that writes `User-agent: CCBot/2.0` + `Disallow: /` while wildcard says `Allow: /` is reported as "allowed by default" — the opposite of the truth. RFC 9309 §2.2.1 and Google both match the robots.txt token as a prefix of the crawler product token, not by equality. Fix: normalize (strip `/version`) and prefix-match.

3. `isBlanketBlocked` only recognizes the literal path `/`. `Disallow: /*` and `Disallow: *` — both seen in the wild and both honored as full blocks by Google/OpenAI — are missed, producing "not blocked" on fully blocked sites.

4. `checkSensitivePaths` is logically inverted for the single most common robots.txt idiom. `return ruleNorm === pathNorm || r.path.startsWith(path) || path.startsWith(r.path);` — when `r.path` is the empty string (from `Disallow:` with no value, which means "nothing is disallowed"), `path.startsWith('')` is ALWAYS true, so every sensitive path is reported "protected". `User-agent: *\nDisallow:` yields a PASS reading "Sensitive paths are protected: /api/, /admin/" on a site that protects nothing. 5. No group-precedence model. Real crawlers use the single most-specific matching group and ignore the wildcard entirely once a bot-specific group exists.
