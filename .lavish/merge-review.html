The only divergence is that 10.9 reads p.structuredData ?? p.jsonLd where 9.8 reads p.jsonLd, and the prose. They filter to the same applicablePageTypes:['content'] set and will return the same verdict on essentially every site, so a dateless blog is penalised twice. 6.11 (time-element) measures the same primary detector — presence of <time datetime> — just counted per page instead of first-hit.
C2 content-discoverability/no-noindex · meta-tags/meta-robots · crawler-permissions/meta-robots-not-blocking
All three read the same field, page.meta['robots'], and fail on the substring 'noindex'. 4.20 (meta-robots) checks ctx.pages[0] only and is a strict subset of 1.13 (no-noindex), which checks ctx.pages[0]'s meta robots plus the x-robots-tag response header. 2.25 (meta-robots-not-blocking) is the same meta check widened to every scanned page. The underlying signal in both cases is 'can an agent find this resource'. The RSS pair is an outright strict subset: content-discoverability/rss-feed.ts's findFeedResult() already iterates every page's headLinks looking for rel=alternate type=application/rss+xml before falling back to /rss.xml,/feed.xml,/atom.xml — and additionally fetch-verifies HTTP 200 — so meta-tags/rss-feed-link.ts can never pass when 1.11 fails. Five audits over one signal: who wrote this and can the identity be verified. 10.2 (author-same-as) is fully contained in 3.15 (author-schema), whose required-property list is literally ['name','jobTitle','sameAs','affiliation'] — 3.15 already warns when sameAs is missing, so a Person schema without sameAs produces two findings with the same fix. 10.1 (named-author) and 3.15 both walk JSON-LD Article/BlogPosting author objects for a name; 10.1 adds two extra fallbacks (meta[author], visible [class*=author]/[class*=byline] text) and a generic-name blocklist ('Staff','Admin','Team'). 4.2 (meta-author) checks exactly one of those fallbacks — bare presence of <meta name="author"> — with no generic-name filtering, so it can pass on content 10.1 rejects. 10.3 (author-page) re-walks the same author objects, differing only in that it reads author.url and fetch-verifies HTTP 200.
C5 content-discoverability/canonical-links · meta-tags/canonical-url
Both check for <link rel="canonical">. 1.17 iterates every page via $('link[rel="canonical"]').attr('href') and reports coverage; 4.3 reads only ctx.pages[0].headLinks and additionally asserts the href is absolute (startsWith('http')). C6 accessibility/aria-landmarks · semantic-html/main-element · semantic-html/header-footer
7.2 (aria-landmarks) checks the homepage for four landmarks using selectors that are OR'd with the plain HTML elements — $('main'), $('header')/[role=banner], $('footer')/[role=contentinfo], $('nav'). 6.3 (main-element) checks $('main').length across pages; 6.5 (header-footer) checks $('header') and $('footer') across pages. 7.2 is therefore a superset of 6.3 and 6.5 on page one, differing only in page breadth and in also covering <nav>.
